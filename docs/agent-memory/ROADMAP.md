# ROADMAP

## M1: full GTA 2 world geometry

Only M1-001 is initially issued. The numbered entries below are ordered planning slots, not additional READY board tasks. Promote them after reviewing predecessor code and results. Each implementation slot targets 1–2 hours unless stated otherwise; split further if evidence reveals more work. All retain the fixed owner policy and existing checks.

1. **M1-001: unit-block faces, 30–45 minutes.** Pure scene geometry for a lid and four walls. Five headless doctests check coordinates, indices, winding, area, translation and seams. No predecessors.
2. **Geometry conventions and evidence.** After 1, write docs/specs/world-geometry.md in original words. Resolve GMP level-to-height mapping, face-local axes, drawable-face selection, flat/collision flags and projection requirements. Label each rule by evidence and record unknowns. Correct the stale CMAP header comment. Gate: every rule needed by step 4 has a source or an explicit unresolved status; unresolved rules cannot be presented as faithful.
3. **Face UV transforms.** After 2, implement CPU corner UVs and atlas mapping. Gate: independent expected-corner tables cover five face orientations × four rotations × two flip states, with asymmetric synthetic markers and half-texel bounds.
4. **Textured ordinary block mesh.** After 1–3, assemble selected lid/wall faces into an indexed mesh. Gate: synthetic fixtures cover absent faces, visible faces without collision flags, collision-only words and tile limits. Unsupported slopes are diagnosed, not silently rendered as faithful cubes.
5. **Multiple-level map assembly.** After 4, traverse bounded regions through all eight levels using synthetic GmpWriter fixtures. Gate: stacked blocks, gaps, bridges, nonzero column offsets and world edges produce exact expected heights/counts and deterministic meshes. Retain faces conservatively until culling is proven safe.
6. **World projection.** After 2 and 5, add render-independent projection math and a diagnostic camera. Gate: CPU tests cover known projected points, near/far depth, aspect changes and visible raised walls. Distinguish diagnostic projection from original-game camera calibration.
7. **Triangle shader path.** After 3 and 6, add a separately buildable world vertex layout and MSL/GLSL/HLSL shaders without switching the application. Gate: layout assertions, SPIR-V freshness and shader compilation on supported platforms.
8. **Offscreen world rendering and depth.** After 5–7, upload a small synthetic mesh and render it with a depth attachment. Gate: overlapping faces yield the same checked interior pixels under reversed submission order; nearer geometry wins. Check GPU resource cleanup and error paths.
9. **Transparency and depth regression.** After 8, implement the evidenced tile alpha behaviour. Gate: synthetic opaque/transparent texels reveal lower levels correctly in both draw orders, including a transparent foreground wall. Existing quad rendering still passes.
10. **Application world view.** After 8–9, connect map geometry, camera, atlas and window/offscreen paths. Gate: synthetic world renders in both modes; resize/minimise/restore maintains correct colour/depth targets. Existing controls and prototype simulation are not expanded.
11. **Slope specification and coverage inventory.** After 2, before 12, classify all 64 slope encodings and inventory those present across 17 local maps. Gate: docs/specs/world-slopes.md identifies topology, height fractions, orientation, special markers and invalid/reserved codes with provenance. Store only specifications and aggregate statistics, never original geometry dumps.
12. **First inclined-surface family.** After 4 and 11, implement one evidenced gradient family in every direction, including its wall profiles. Gate: independent expected heights, normals, areas, UVs and neighbouring ramp joins pass headlessly.
13. **Remaining gradient families.** After 12, implement the remaining documented gradient variants. Gate: every defined gradient code has independent topology/height tests, including partial-height joins. Split by family if needed to keep sessions within two hours.
14. **Diagonal slopes.** After 13, implement diagonal topology in every orientation. Gate: independent footprints, triangle counts, winding, wall clipping and UV tests pass; synthetic offscreen images show no missing or doubled surfaces.
15. **Three-sided slopes and marker exceptions.** After 14, implement three-sided topology and the evidenced handling of lid 1023 exceptions. Gate: all orientations pass independent CPU tests and synthetic image checks; marker faces never sample the atlas white slot accidentally.
16. **Local 17-map geometry gate.** After 5 and 12–15, add an explicit data-enabled validation command. Gate: exactly 17 maps pass finite-coordinate, index, height, slope and texture-policy checks with zero unexplained unsupported cases. Missing data fails the explicit gate while ordinary CI remains asset-free. Reserved animated tiles need a documented static policy; animation remains later work.
17. **Original orientation comparison.** After 10 and 16, add a local comparison protocol and runner using original-game reference captures outside the repository. Gate: reviewed cases cover lids, all wall directions, rotation/flip combinations present in original data, and representative slope families. Record camera calibration, masks and justified tolerances before scoring; retain all original images locally.
18. **District review.** After 17, capture Downtown/wil, Residential/ste and Industrial/bil at fixed views selected to expose walls, slopes, height differences and occlusion. Gate: at least one overview and one detail per district, all outside the repository, plus numeric comparison results and Astra visual review. Resolve fidelity failures before performance work.
19. **Geometry benchmark baseline.** After 18, add reproducible CPU build and renderer measurements. Gate: record hardware/backend/compiler/revision, views, mesh memory/counts, uploads, construction time and median/p95 frame time; use 120 warm-up frames and 600 measured frames, repeated three times. Synthetic CI workloads contain no original assets.
20. **CPU geometry cache.** After 19, cache meshes by map/region identity. Gate: 600 unchanged frames cause zero rebuilds; map replacement invalidates affected entries; cached and uncached geometry agree exactly. Record memory and build-time changes.
21. **Persistent GPU buffers.** After 20, retain static vertex/index buffers with explicit lifecycle management. Gate: zero static mesh uploads across 600 warmed unchanged frames, correct replacement/cleanup, and identical synthetic render results.
22. **Visibility optimisation.** After 21, add conservative bounds/chunk selection that accounts for elevation. Gate: camera-edge and tall-building tests show no disappearing geometry; the unculled reference matches visible results. Only add neighbour-face removal if original semantics and alpha behaviour justify it.
23. **Regression thresholds and platform parity.** After 22, enforce deterministic geometry/render/caching checks and compare performance with step 19. Gate: no unexplained median/p95 regression over 10% on the same machine and settings, reviewed memory limits, and passing synthetic world tests on Metal/D3D12/Vulkan. Turn the world-render test into a required check in native-ci without modifying AWS workflows or weakening existing checks.
24. **M1 acceptance audit.** After 23, rerun the 17-map gate, original comparisons, district captures, benchmarks and all native checks on the integration revision. Gate: every milestone criterion has inspectable evidence; unresolved fidelity or backend failures keep M1 active.

## After M1

Sprites and animated textures; world objects; player character and controls; world collisions; vehicles; car physics; pedestrians; AI; police and wanted level; gangs and respect; weapons and damage; missions and scripts; UI/HUD; audio; save state; remaining original mechanics; optimisation and platform parity; full-gameplay regression; behavioural comparison with the original; stable release candidate.

The fixed goal does not change. AI, vehicle physics and missions cannot start before M1 acceptance. Cloud work is not authorised by this roadmap. Original-game references must remain local; if a required reference cannot be obtained within policy, report the concrete blocker. Agents may identify a release candidate; only the human declares the project finished.
